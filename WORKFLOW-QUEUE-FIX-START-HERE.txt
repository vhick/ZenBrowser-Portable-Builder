ZEN BROWSER PORTABLE — FIX FOR QUEUED GITHUB ACTIONS RUNS

WHY THIS FIX:
The previous builder included a workflow-wide concurrency group named
zen-portable-manual with cancel-in-progress: false. If GitHub treats an old
run as active, a newer manual run may wait behind it indefinitely.
The corrected workflow removes that artificial dependency. It does NOT
change the Zen executable, portable launcher, profile, cleanup logic, or icon.

IMPORTANT: This only removes the concurrency lock. It cannot fix a genuine
GitHub Actions runner outage, disabled Actions, or an account quota problem.

USE THE SMALL WORKFLOW-ONLY PATCH (EASIEST):
1. Unzip the small patch on your PC.
2. In GitHub Desktop, open Repository -> Show in Explorer.
3. Copy the extracted .github folder into the repository root, merging and
   replacing .github/workflows/build-zen-browser-portable.yml.
4. Back in GitHub Desktop, check the change, Commit, then Push origin.
5. On GitHub, open Actions -> Build Zen Browser Portable ZIP (Manual).
6. Click Run workflow to start a NEW run on the updated main branch.
   Do not rerun #5 or #6: they were created using the older workflow.
7. A working run should show Set up job and Checkout your portable builder.
8. If it stays queued, check Actions availability/account restrictions instead.

ALTERNATIVE: Use the FULL builder ZIP to replace the builder repo files.
Preserve any customizations, and DO NOT replace your installed portable Data.

KEEP ALL EXISTING USER DATA:
Do not overwrite the already installed ZenBrowserPortable\Data folder.
The builder runs only when you manually trigger Actions; the portable launcher
runs startup and cleanup scripts itself during normal browser use.
